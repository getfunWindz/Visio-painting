# 软件工程制图符号规范

坐标约定：单位**厘米**，原点在**左上角**；`Draw(cx, cy, w, h)` 中的 `(cx, cy)` 是图形**几何中心**。

---

## 1. UML 用例图

| 元素 | 画法 | 引擎调用 |
|---|---|---|
| 参与者 | 火柴人：圆头 + 竖身 + 横臂 + 两条斜腿，姓名在图形下方 | `d.actor(cx, cy, "普通用户")` |
| 用例 | 椭圆，名称居中；填充浅蓝、描边深蓝 | `d.oval(...)` |
| 系统边界 | 矩形，边界名称置于**框上方居中**（不要压在框线上） | `d.rect(...)` + `d.text(...)` |
| 关联 | 实线，**无箭头**，从参与者指向（连到）用例边缘 | `d.line(...)` |
| 包含 / 扩展 | 虚线 + **开口箭头** + `«include»` / `«extend»` 标签 | `d.include(a, b, label="«extend»")` |
| 泛化 | 实线 + 空心三角箭头 | 手绘 polyline |

排布约定：

- 用例列必须**在系统边界内水平居中**：列中心 = 边界中心。常见错误是列贴在左侧、右侧留大片空白。
- 有左右两个参与者时，用例列居中后两侧连线自然对称。
- `«include»` 标签放在连线**中点法向偏移 0.4cm** 处，不要压线；两条以上平行关系要错开纵向间距，否则标签会挤在一起。
- 参与者姓名与相邻元素至少留 0.3cm，避免姓名压住连线或边界。
- **关联线从参与者躯干中线引出**（起点取 `(cx, cy)`），不要从图形外侧的空白点或手臂端点引出；先画线、后画角色，让躯干压住线头。
- **用例一律单列**。双列时右列用例没有可用的引线路径（左列会挡住），实践中极易漏连；若确需双列，必须逐个核对每个用例都有且仅有一条关联线。
- **同侧放置两个参与者时，纵向间距 ≥3.9cm**（火柴人含姓名约 3.5cm 高），否则头脚重叠。可把该侧需要的用例在列中上下拉开，或以不同高度放置两个角色。
- 交付前逐个数一遍：`用例数 == 关联线条数 - 额外参与者连线数`，确保没有孤立用例。

## 2. UML 活动图

| 元素 | 画法 | 引擎调用 |
|---|---|---|
| 初始结点 | 实心黑圆，直径 0.55cm | `d.start_node(cx, cy)` |
| 活动 | 圆角矩形（圆角 0.18cm） | `d.rrect(...)` |
| 判定 | 菱形（四条线段闭合，不填充） | `d.diamond(cx, cy, 4.4, 2.0, "参数校验\n通过？")` |
| 终止结点 | 牛眼：外圆 + 内实心圆 | `d.end_node(cx, cy)` |
| 控制流 | 实线 + 实心箭头 | `d.line(..., arrow_end=ARROW_FILL)` |
| 分支标注 | `是` / `否`，放在箭头**起点一侧**、偏离线 0.26cm | `d.text(...)` |

排布约定（最易翻车）：

- **纵向间距**：活动框高 0.86cm 时，相邻活动中心距 1.14cm（间隙 0.28cm）；菱形与相邻活动之间留 **0.45cm** 以上，否则 `是/否` 标签没地方放。
- **菱形尺寸**：文字每行 4 个汉字时，菱形取 4.4×2.0cm。字号不要超过 8.5pt，否则文字顶到菱形斜边。
- **主流程单列、异常分支右列**：右列元素中心距主列 5cm 以上，回退连线沿右列外侧上行，**不要横穿主流程**。
- **终止结点标签**放在结点右侧 1.7cm 处（不要放正下方，会与圆周重叠）。
- **四周留白 ≥ 0.5cm**：EMF 会裁掉 1.4%，贴边的结点会被切掉一半。
- 一张图的高度以 ≤17cm 为宜（A4 版心高 24.7cm，还要留图题与正文）。

## 3. UML 时序图

| 元素 | 画法 |
|---|---|
| 对象头 | 矩形，名称居中，位于页面顶部 |
| 生命线 | 从对象头底部向下的**虚线** |
| 激活条 | 生命线上宽 0.26cm 的窄矩形，浅灰填充 |
| 同步消息 | 实线 + 实心箭头 |
| 返回消息 | 虚线 + **开口箭头** |
| 自消息 | 折线回环（右→下→左），末端开口箭头，标签放在回环**上方** |

约定：

- 消息标签统一编号（`1.`、`2.`…），放在消息线上方 0.3cm。
- 第一条消息的 y 起点要留出对象头高度 + 0.55cm，否则标签压住头框。
- 生命线之间水平间距 ≥ 2.6cm，否则长标签会与相邻生命线交叠。
- 生命线底部收在最后一条消息下方 0.5cm。

## 4. 陈氏 E-R 图

| 元素 | 画法 | 引擎调用 |
|---|---|---|
| 实体 | 矩形 | `d.rect(..., fill=C_BLUE_L)` |
| 属性 | 椭圆，白底绿边 | `d.oval(..., fill=WHITE, line_color=C_GREEN_D)` |
| 主键属性 | 属性名**加下划线** | `align_underline=True` |
| 联系 | 菱形，橙边 | `d.diamond(...)` |
| 连线 | 实线，**无箭头** | `d.line(...)` |
| 基数 | `1` / `n` / `m`，靠近所修饰的一端、线段上方 0.26cm | `d.text(...)` |

关键：

- 连线必须**画到图形边界**而不是中心，否则线会穿过菱形里的文字（最典型的观感缺陷）。引擎的 `_edge()` 按 rect / ellipse / diamond 三种边界求交。
- 实体属性图把属性**单行横向排开**，每列等宽（≤1.95cm），实体在下方居中，连线呈扇形不发散交叉。
- 局部 E-R 图沿一条主线排布（实体—菱形—实体—菱形—实体），避免斜向连线交叉。
- 汇总 E-R 图用「主干 + 上下支线」：主干放核心实体与联系，支线分别向上、向下挂附属实体。

## 5. 分层架构图

- 结构：外层虚线容器（浅灰底）+ 左侧层名带（深色底、白字）+ 组件框（白底或浅蓝底）。
- 层名带宽度需 ≥ 1.85cm 才能容纳「基础设施层」5 个汉字一行；否则会折成两行。
- 组件框宽度按 `(可用宽度 - 间距) / 个数` 分配，**不要硬编码固定宽度**；再用 `fit_size()` 定字号，避免「智能创作服务」这类 6 字名称折行。
- 跨层的横切关注点（安全、运维保障）用右侧竖带表示。
- 相邻层之间是否需要箭头：分层架构默认不画箭头，靠上下次序表达依赖；画了反而与「调用关系」混淆。

## 6. 模块结构图

- 两级结构（系统 → 子系统）用「根结点 + 一行子结点 + 正交连线（母线下折 + 横线 + 子线上折带箭头）」。
- 三级结构（子系统 → 模块 → 功能点）**不要**把功能点横排在模块正下方：3 个功能点挤在 3.6cm 宽里，单框只有 1.1cm，四个汉字必然逐字换行。
  可行的两种做法：① 只画两级，功能点在正文里叙述；② 功能点改为纵向排列，模块框内用「模块名 + 功能点列表」的文本形式表达。
- 连线横线的两端严格止于最外侧子结点的中心线，不要外延。

## 7. 网络架构图（Visio 内置模具）

用 `Stencils` 加载 Visio 自带网络图元，比纯矩形框清晰得多：

| 角色 | 模具键 | 图元名 |
|---|---|---|
| 用户终端 | `pc` | `PC`、`笔记本电脑`、`平板设备` |
| 防火墙 | `per` | `防火墙` |
| 反向代理 | `srv` | `代理服务器` |
| 应用服务器 | `srv` | `应用程序服务器`、`Web 服务器` |
| 数据库 | `srv` | `数据库服务器` |
| 缓存 / 通用服务器 | `srv` | `服务器` |
| 文件 / 对象存储 | `srv` | `文件服务器` |
| 网络云 | （自绘） | `Stencils.cloud()` →「修订云形」 |
| 路由器 / 交换机 | `per` | `路由器`、`交换机` |

排布约定：

- 图元**不带自带文字**，标签另外画在图元下方 0.42cm（自带文字位置各异，容易压住图形）。
- 图元按包围盒左对齐、等间距（0.8–1.0cm），连线取图标垂直中心（`bbox` 中心 ± 微调）。
- 链路协议标注（HTTPS / HTTP / API）放在连线上方 0.27cm，字号 7pt，宽度不超过间距。
- 服务器组用「总线 + 三条下垂箭头」表示，总线从上游节点的底部引出。
- 图例不必写，标签即图例。

## 8. 通用规范

- 线宽：轮廓 0.7–1.0pt，连线 0.8–0.9pt；同一张图内保持一致。
- 字号：图内文字 8–9.5pt；连线/基数标注 7–8.5pt。插入 Word 时按 1:1 还原，故此处即最终字号。
- 配色：深蓝描边 + 浅蓝填充为主，橙色表示判定/联系，绿色表示属性/安全。所有颜色在黑白打印下仍可区分（靠明度差）。
- 字体：中文宋体（与正文一致），西文 Times New Roman。
- 每张图四周留白 ≥ 0.35cm（应对 EMF 的 1.4% 裁剪）。
